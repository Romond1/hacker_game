# Phase 2.3 Game Feel Implementation Plan

**Goal:** Make the existing game visibly and audibly responsive without changing gameplay, persistence, economy, or server authority.

**Architecture:** Add small reusable presentation primitives and finite UI state machines. Use CSS-first animation and extend the existing centralized WebAudio synthesizer. Keep all data and mutations in their current owners.

**Tech:** React 19, TypeScript, Vitest, Testing Library, CSS, Vite, Playwright verification scripts.

## Task 1: Shared feedback primitives and sound

**Files:** `src/components/gamefeel/*`, `src/effects/gameEffects.ts`, shared CSS, new focused tests.

1. Add failing tests for progress semantics, operator messaging, story-step progression/skip, reduced-motion counter output, sound-theme lookup, and mute/throttle behavior.
2. Run the focused tests and confirm the new expectations fail.
3. Implement `AmbientLayer`, `ProgressMeter`, `OperatorMessage`, `RewardCounter`, and `StoryBeatSequence` with minimal public APIs.
4. Extend the sound manager with semantic effects and a replaceable default theme; keep it user-gesture driven and centrally throttled.
5. Add shared focus, press, card-state, ambient, overlay, and reduced-motion CSS.
6. Run focused tests, typecheck, and commit.

## Task 2: Mission surfaces and completion sequence

**Files:** reusable briefing/template/runner and reward components, their CSS and tests.

5. Run mission/progression tests, typecheck, and commit.
